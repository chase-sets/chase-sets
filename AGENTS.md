## Secrets for agents

Agents get dev/test secrets only through `scripts/agent-secrets/with-secrets.ps1`, which injects one Bitwarden Secrets Manager project as environment variables into a single command: `pwsh -NoProfile -File scripts/agent-secrets/with-secrets.ps1 -Command '<cmd>'`. From a seat older than this helper, run `../main/scripts/agent-secrets/with-secrets.ps1` instead. Use `-ListKeys` to see which key names exist and `-Check` to confirm the token can read the project. The helper replaces the token and every project value with `[redacted]` only in its own stdout and stderr; it refuses with `unscrubbable-value`, running nothing, when a value is shorter than 8 characters or not printable ASCII. It cannot see files, sockets, or transformed values, so never write injected values to a file. Never print, log, or echo injected values, never call `bws secret get`, and never use the `bw` CLI or Todd's personal vault. Production and live-money credentials are not in this project; changes that need them go through CI/deploy workflows. The project may hold only the [agent tier](docs/runbooks/credential-rotation.md#agent-tier) recorded in the credential inventory, and every other entry is CI/deploy-only. The helper refuses with `tier-violation`, naming the key, while the project holds anything else, and with `inventory-unavailable` when it cannot read the inventory. `denied` means the lane runs with `CHASE_SETS_AGENT_SECRETS=deny` and may not use secrets. If the helper reports `missing-token` or an expired token, hand Todd `scripts/agent-secrets/set-bitwarden-agent-token.ps1` rather than asking for the token value.

## Bounded tool output

- Never dump the full environment (e.g. `Get-ChildItem Env:`, `env`) to output.
- Never dump a whole directory tree; list a specific path or use a filtered glob.
- Read files in ranges (`Get-Content -TotalCount`/`-Skip`, `sed -n`); never read a file `-Raw` above about 200 lines.
- Find files first with `rg -l`, then search only those named files or a narrow subtree. Line-count limits alone do not bound line length: cap width with `rg --max-columns`/`--max-columns-preview`, or extract narrow structured fields (e.g. `jq`) instead of printing a raw long line.
- Pipe long command output through `Select-Object -First`/`tail` rather than printing it whole.
- When a command's output would exceed one screen, redirect it to a file under the worktree's ignored scratch path and read only the relevant slice.
- Prefer `git diff --stat` before running a full `git diff`.
