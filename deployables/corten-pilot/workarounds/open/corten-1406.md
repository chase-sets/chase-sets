# [corten-run/corten#1406 A GET data-patch form redraws the page's part for a new address but leaves the old address, so a filter is lost on reload and the page's other links keep the old one](https://github.com/corten-run/corten/issues/1406)

The marketplace's Load more ([search.rs](../../marketplace/src/search.rs), `kept_address`) is a GET `data-patch` form, so the rows it adds leave the history entry at the address the page was drawn from, and Back from an item drew only the first page. The patch's Load more form connects with `search.grown` ([search.js](../../marketplace/src/views/search.js)), which puts the address of the rows the page now shows (`more=`) in place of the history entry's with `history.replaceState`, as corten-ui's tabs do. Remove `grown` and the `kept` prop of `LoadMore` once Corten writes a patch's address itself.
